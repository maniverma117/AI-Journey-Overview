


# 11. Taints and tolerations

GPU nodes are expensive.

You usually don't want ordinary workloads consuming them.

So you might taint:

```text
gpu=true:NoSchedule
```

on GPU nodes.

Then:

```text
ordinary pod
```

doesn't get scheduled there.

But your vLLM pod has:

```yaml
tolerations:
  - key: "gpu"
    operator: "Exists"
    effect: "NoSchedule"
```

Now:

```text
ordinary pod
       ↓
GPU node ❌

vLLM pod
       ↓
GPU node ✅
```

This creates a dedicated GPU workload pool.

---

# 12. Taint vs toleration

Very important:

### Taint

Lives on:

```text
Node
```

and says:

> Keep pods away unless they tolerate me.

### Toleration

Lives on:

```text
Pod
```

and says:

> I am allowed onto this tainted node.

But a toleration does **not** mean:

> Schedule me there.

That's where people get confused.

You still need:

```text
nodeSelector
affinity
resource requests
```

if you want to target those nodes.

# 22. Now we get to DRA

Kubernetes historically used:

```text
nvidia.com/gpu
```

as a simple extended resource.

But modern Kubernetes introduces:

# Dynamic Resource Allocation — DRA

The idea is:

> Hardware resources can be allocated through richer, structured resource claims rather than only simple integer resources.

This is especially interesting for:

```text
GPUs
accelerators
network devices
specialized hardware
```

Kubernetes DRA is designed to let workloads request specialized resources through resource claims and lets drivers participate in allocation decisions.

---

# 23. Why DRA exists

Imagine your request isn't simply:

```text
1 GPU
```

but:

```text
1 H100
with:
  specific capabilities
  topology constraints
  partitioning requirements
  special configuration
```

An integer:

```text
nvidia.com/gpu: 1
```

doesn't express all of that elegantly.

DRA provides a richer abstraction.

Conceptually:

```text
Pod
 │
 ▼
ResourceClaim
 │
 ▼
DRA driver
 │
 ▼
hardware allocation
```

# 24. Device Plugin vs DRA

Think:

### Device Plugin

```text
"I have 8 GPUs."
```

Simple resource advertisement/allocation.

### DRA

```text
"I need a GPU resource matching these constraints."
```

More expressive resource allocation.

So:

```text
Device Plugin
    ↓
simple GPU resource

DRA
    ↓
structured resource claim
```

The two approaches are part of Kubernetes' evolving device-management model; exact support depends on the Kubernetes version and driver implementation.

# 26. MIG

Now another important concept.

Some NVIDIA GPUs support:

# Multi-Instance GPU — MIG

Instead of:

```text
one physical GPU
       ↓
one workload
```

you can partition a supported GPU into isolated GPU instances.

Conceptually:

```text
Physical GPU
┌───────────────────────────────┐
│                               │
│       H100 / A100             │
│                               │
└───────────────────────────────┘
          ↓ partition
┌────────┬────────┬─────────────┐
│ MIG 1  │ MIG 2  │ MIG 3       │
└────────┴────────┴─────────────┘
```

Each partition has allocated compute/memory resources according to supported MIG profiles.

---

# 27. MIG is not GPU time-sharing

Important distinction.

### MIG

Physical partitioning:

```text
GPU
 ├── instance A
 ├── instance B
 └── instance C
```

### Time slicing

Multiple workloads take turns using the same physical GPU.

Conceptually:

```text
time →
A A A B B B A A C C
```

MIG provides stronger hardware-level isolation than ordinary time-sharing.

---


```text

       ↓
```

# 34. Preferred vs required affinity

```text
must match
```

```text

```

### Preferred

```text

```

but Kubernetes may choose another node.

For a workload that **requires** H100:

```text

```

is usually the appropriate semantic.

For:

> Prefer H100, but L40S is acceptable.

# 44. Don't use `/healthz` too early

A pod can technically be:

```text
Running
```

while the model isn't actually ready to serve.

You need readiness semantics that reflect:

```text
process alive
+
model loaded
+
GPU initialized
+
server accepting requests
```

Conceptually:

```text
liveness:
"Is vLLM process alive?"

readiness:
"Can this replica actually serve inference?"
```
